# Coding Standards

Apply Clean Code and SOLID principles pragmatically.

- Prefer KISS and YAGNI over speculative abstractions.
- Use descriptive names.
- Prefer small, focused functions.
- Avoid deeply nested control flow.
- Avoid duplicated business rules.
- Prefer explicit code over clever code.
- Write comments to explain *why* when the reason is not clear from the code, rather than restating what the code does.
- Do not introduce interfaces, base classes, factories, domain services, additional architectural layers, or similar abstractions without a concrete justification.
